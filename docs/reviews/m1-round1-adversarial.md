Read-only review of `m0-final...HEAD`; no files modified or mutation tests executed.

1. **High — Symlink aliases bypass protected-path checks.** `internal/web/routes_mutate.go:197,266,360,413` checks only `fsx.Clean` paths, which are lexical. Workers resolve parent symlinks (`internal/fsops/mutate.go:63,115,160`). With `/tmp/config-alias -> /etc/config`, an admin can delete `/tmp/config-alias/smb.conf` without confirmation. Aliases into the installation tree similarly bypass denial. No race is necessary. **Minimal fix:** resolve parents using matching filesystem semantics, check both requested and resolved paths, and dispatch the checked resolution; preserve final-link semantics for rename/delete.

2. **High — Rename omits destination deletion protection.** `internal/web/routes_mutate.go:266` checks `OpRename(from)` and `OpCreate(parent(to))`, never `OpDelete(to)`. On a NAS where `/etc/config` is a symlink, renaming a same-filesystem regular file onto `/etc/config` with `overwrite:true` replaces that protected link without confirmation: `/etc` permits creation. Source deletion rules are also omitted; `/etc/config` itself permits `OpRename` despite denying `OpDelete`. **Minimal fix:** check source removal, destination replacement, destination entry protection, and destination-parent creation; combine all verdicts.

3. **High — HEAD can change settings without CSRF or forced revalidation.** `internal/web/server.go:119,280` accepts HEAD wherever GET exists, but dispatches every settings method except GET to `postSettings`. An authenticated admin’s HEAD request with body `{"readOnly":false}` changes persistent settings without `X-QFM-CSRF` or Origin validation and can use cached authentication. This is a concrete protocol bypass; browser exploitation depends on sending a HEAD body. **Minimal fix:** dispatch GET/HEAD to the read handler and only POST to the mutation handler.

4. **High — Confirmation tokens are replayable through alternate encodings.** `internal/guard/confirm.go:103` indexes spent tokens by the supplied string. Go’s Base64 decoder ignores CR/LF, so a redeemed token `T` can be redeemed again as `T+"\n"`, then with additional newlines, until expiry. JSON escapes transport these characters. **Minimal fix:** key spent state by decoded token bytes or authenticated nonce, or reject every noncanonical encoding. `Strict()` alone does not reject newlines.

5. **Medium — Tokens do not bind rename direction or destructive options.** `internal/guard/confirm.go:67,94` sorts paths; `internal/web/routes_mutate.go:267` supplies `[from,to]`. A token for renaming `/etc/config/a` to `/etc/config/b` also authorizes the reverse rename. Changing `overwrite:false` to `true` is likewise unbound and can destroy the destination. **Minimal fix:** authenticate a structured operation containing ordered source/destination roles and relevant options; sort only unordered batch targets.

6. **High — `parents:true` bypasses the `/share` creation ban.** `internal/web/routes_mutate.go:197,202` checks only the supplied parent. Posting `{"dir":"/share/new","name":"child","parents":true}` checks `/share/new`, which is allowed, then creates `/share/new` directly on the RAM disk. **Minimal fix:** disable recursive parent creation for M1, or check every parent in which an intermediate directory will be created. Also check the final target against entry-specific protections such as `.zfs`.

7. **High — Batch delete continues after read-only is enabled.** `internal/web/routes_mutate.go:413` ignores every per-item guard error except `ErrProtected`. If an administrator enables read-only during a batch, subsequent checks return `ErrReadOnly`, yet deletion continues. Because read-only short-circuits protection checks, those iterations also stop recognizing protected items. **Minimal fix:** handle every guard error; only tolerate `ErrConfirmRequired` when the batch has actually redeemed its matching token.

8. **Medium — Concurrent settings changes can leave disk and guard disagreeing.** `internal/web/routes_admin.go:64,71` releases `cfgMu` before updating the guard. Request A can persist false and pause; B persists/applies true; A then applies false. The file says read-only while writes remain enabled. **Minimal fix:** serialize persistence and the live guard update in the same critical section, including memory-only toggles.

9. **Medium — Required safety confirmations are missing.** `internal/web/routes_admin.go:37` disables read-only using only the existing session, without decision 7’s password challenge. `internal/web/routes_mutate.go:361,387` permanently deletes ordinary files without server-side confirmation and supplies no measured byte count, so even a multi-gigabyte file bypasses the byte threshold. Trash is deferred, but decision 10 requires level-2 confirmation when deletion is permanent. **Minimal fix:** implement password reauthentication before disabling read-only and enforce permanent-delete confirmation server-side using worker-supplied metadata.

10. **Medium — Audit evidence can disappear while mutations succeed.** `internal/audit/audit.go:140,185` drops all event types on overflow and ignores disk-write failures. A denial flood can occupy the synchronous QuLog drain, filling the queue so a later mutation loses both intent and result. Disk-full failures are silent and do not increment the overflow counter. Authentication/CSRF failures, confirmation failures, and settings-save failures also bypass structured audit. **Minimal fix:** require acknowledged intent recording before dispatch, protect milestone delivery, surface sink failures, and audit those rejection paths. Aggregate overflow notices are useful but cannot replace lost security milestones.

Other checks were sound within these limits: non-admin mutations retain explicit kernel credentials and are intentionally allowed when read-only is off; clients cannot select `Principal.Root`. Literal `/` and `/etc` deletion is refused. Known mount roots are denied, and M1 deletion never recursively removes their contents. Batch tokens bind the full path multiset, preventing substitution of another item. HMAC verification prevents forgery; expiry holds with subsecond rounding slack. Existing read-route authentication remains intact. JSON escaping and QuLog’s single-argument invocation/line cleaning prevent direct log or shell injection.

**Residual risks:** Linux/QNAP behavior was reviewed statically, not exercised. Mount-table freshness, concurrent namespace changes, rename’s documented overwrite race, and ambiguous outcomes after RPC failure remain. Audit durability across crashes is not guaranteed by asynchronous enqueueing.
