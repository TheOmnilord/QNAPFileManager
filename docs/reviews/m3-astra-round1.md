# M3 permissions and properties — Astra round 1 of 10 (2026-09-17, gpt-6-astra, effort high)

The owner lifted the Astra pause on 2026-09-17 and set a ceiling of ten Astra rounds per milestone, M3 and M4
counted separately. This is M3's first. Reviewed: commit 73955c4 (staged in a detached worktree so `codex exec
review` sees it as the diff) against `docs/design/m3-contract.md`; the five Opus rounds before it are
`m3-round1..5.md`. Judged by Claude Fable 5.1.

Normal review: 16 findings. Adversarial ("robustness and isolation") review: 12 findings, 7 of them the same
defects. Unique findings: 21.

| # | Finding | Owner | Judgement |
|---|---|---|---|
| 1 | P1: a dataset mounted after start-up gets a capability row with an empty `ACLBackend` (`Platform.Refresh` carries probed fields only for mounts it already knew); `chmodACLNotice` switches on the backend and an empty one is *no warning*, even under `aclmode=discard`. Not the accepted mount-after-token race — the dataset can exist before the request. | routes + engine | **Accepted.** New mounts are probed on refresh (bounded, cached, as at start-up); and an empty backend on a storage mount is graded pessimistically (L2, the unknown suffix) instead of silently. |
| 2 | P1/P2: `Platform.For` and `MountFor` run `normalizePath`, which turns `\` into `/` and cleans — so a Linux file literally named `danger/..\safe/file` is graded on the `safe` dataset while chmod changes the inode on `danger`. `aclInfoFor` and `newACLProbe` in the worker repeat it. | routes + engine | **Accepted.** `ForLiteral` (M2-C round 3) exists for exactly this; every ACL decision — `mountFacts`, the crossing rung, `aclInfoFor`, `newACLProbe` — uses the literal lookup. |
| 3 | P1: `perm.NFS4State` calls an ACL trivial when every who is a special principal and no inherit flag is set — ignoring ACE **type** and **mask**: `EVERYONE@ DENY DELETE` or `GROUP@ ALLOW WRITE_ACL` is "trivial" and a `discard` chmod destroys it without L2. | engine | **Accepted.** Trivial additionally requires every ACE to be ALLOW, and no `WRITE_ACL`/`WRITE_OWNER` on `GROUP@`/`EVERYONE@` (the bits a mode cannot express). A DENY of any kind is non-trivial. Contract §6.1 amended. |
| 4 | P1: `Props` probes the ACL by **pathname** after `canonicalLeaf` held the inode, and the chmod is a separate RPC with no precondition — swap a non-trivial file over the name between the two and the ACL is discarded without L2. The display-only residual does not cover an authorisation input. | engine + routes | **Accepted.** `Props` reads the attribute through `/proc/self/fd/N` of the held leaf; `ChmodReq` carries `Expect *wproto.ACLExpect{State, Identity}` and the worker re-probes on the held descriptor and refuses `changed` when the identity or the state differs from what the ladder graded. |
| 5 | P1: `entryACLFacts` lets the worker's `ACLInfo.Backend` overwrite the daemon's known backend; a non-root worker whose `Detect()` could not read the dataset root's ACL answers `none`, and the discard warning disappears. | routes | **Accepted.** The route keeps the more pessimistic of the two; a worker `none` never downgrades a known `nfs4`/`posix`. |
| 6 | P1 (adv): recursive chmod/chown checks the guard on the roots only; `/share/CACHEDEV1_DATA/.qpkg` recursively reaches the daemon's own config, credential and audit files, which naming them directly refuses. | routes | **Accepted.** `Guard.Contains` over every root, as the transfer routes do. |
| 7 | P1/P2: non-root directories are closed by the walker before `Post`; `applyEntry` reopens the **name** without an identity check, so a directory swapped in during its children's traversal receives the post-order chmod/chown (and a mount placed there bypasses the crossing decision). | engine | **Accepted.** The reopened directory is compared (dev, ino) with what was traversed; a mismatch is `changed` for that entry. |
| 8 | P2: a directory the worker cannot enumerate (owner-set `0000`) is skipped without attempting the change on the directory itself, so a recursive repair cannot repair exactly the directories that need it. | engine | **Accepted.** The metadata change is attempted on the held reference; the traversal failure is reported separately. |
| 9 | P2: chmod **jobs** hand `ACLUnknown` to `chmodACLNotice`, whose POSIX branch warns only for `ACLPosix` — a two-file job on a POSIX share needs no mask acknowledgement while the same change through the sync route is L1. | routes | **Accepted.** On a POSIX backend an unknown state warns L1, the pessimistic reading. |
| 10 | P2 ×2: the confirmation pre-scan runs `JobSize` straight through `jobRunner.Job` — outside the metadata slots and with the size walk's unbounded entry limit — so concurrent unconfirmed POSTs run many unbounded scans. Contract §13's "nothing in M3 needs admission" overlooked it. | routes (+ engine for the bound) | **Accepted.** The pre-scan takes a metadata slot and carries an entry budget (`modeScanMaxEntries`); a capped scan is `-1`. Contract §13 amended. |
| 11 | P2: a `-1` (unmeasured) scan is stored as `Files: 0`, which `recordCost` discards and `peekScan` rejects, so the confirmed repost rescans the largest trees and can outlive the token. | routes | **Accepted.** The ledger keeps an explicit "capped" outcome and the redemption reuses it. |
| 12 | P2: `perms.js` awaits only the chown job's 202 before submitting the chmod; the two run concurrently in the metadata pool, so `4755` after a chown can land with setuid cleared. | ui | **Accepted.** The dialog waits for the chown job's terminal state before dispatching the mode change. |
| 13 | P2: an octal field showing `0788` dispatches the last valid prefix (`0007`); clearing the field keeps the previous spec. | ui | **Accepted.** Octal validity is tracked and Apply is blocked until the shown value and the spec agree. |
| 14 | P2: `awaitJob` returning null (poll limit) or throwing (transient fetch failure) drops the size job's id, so Stop, close and Recount can no longer cancel it. | ui | **Accepted.** The id is kept until a terminal state; an abandoned poll cancels explicitly. |
| 15 | P2: `workerpool/m3_test.go` runs `InProcess: true`, so the root CI job never applies `alice()`'s credentials — non-owner `EPERM`, member/non-member chgrp, silent setgid drop and mixed-ownership partial success are untested against the kernel. | tests | **Accepted.** Spawned-worker tests under distinct uids in the root job. |
| 16 | P2: no M3 test touches an ACL-bearing object on a real backend; the ZFS and ext4 jobs never see a mask rewrite, a non-trivial badge or a `restricted`/`discard` confirmation. | tests | **Accepted.** ext4 `setfacl` fixture and a hand-written NFSv4 ACE on the ZFS fixture, asserting badge state and the warning — never the kernel's verdict (INV-2). |
| 17 | P2: the listing probe picks one backend from the containing directory for every child; a dataset mounted beneath a POSIX directory is probed for the wrong attribute and badged `none`. | engine | **Accepted.** A child that is a mount point selects its own backend (literal lookup); one page budget. |
| 18 | P3: the byte budget is checked before the size query, not against the attribute's size — a page at 60 KiB reads a 16 KiB attribute in full. | engine | **Accepted.** The remaining budget is compared with the reported size first. |
| 19 | P2 (adv): a regular-file bind mount is not `WalkItem.Mount`, so a non-directory entry outside the tree is changed with `crossMounts:false`; nlink stays 1 so the hardlink rule does not catch it. | engine | **Accepted.** Non-directory entries compare the held leaf's device with the parent's under the same crossing policy. |
| 20 | P2 (adv): the recursive root's `ref.fi` is captured before the subtree walk; a setgid cleared elsewhere during the walk is reinstated by the post-order call from the stale snapshot, and hidden from the diff. | engine | **Accepted.** The held root is re-`fstat`ed immediately before its requested mode is built. |
