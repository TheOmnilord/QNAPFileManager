# M4 polish and release — Astra round 1 of 10 (2026-09-17, gpt-6-astra, effort high)

The owner lifted the Astra pause on 2026-09-17 and set a ceiling of ten Astra rounds per milestone, M3 and M4
counted separately. This is M4's first. Reviewed: commit a2f640c (staged in a detached worktree) against
`docs/design/m4-contract.md`; the four Opus rounds before it are `m4-round1..4.md`. Judged by Claude Fable 5.1.

Normal review: 16 findings. Adversarial review: 13 findings, 9 of them the same defects. Unique findings: 20.

| # | Finding | Owner | Judgement |
|---|---|---|---|
| 1 | P1 (both): `api()` calls `response.json()` unconditionally; the login route answers **204**, so a correct emergency password shows *Request failed (204)* and never reaches `onSignedIn`. Reproduced with the real modules. The cookie is set, so a manual reload works — which is why the hardware smoke test passed. | ui | **Accepted.** `api()` treats 204 / an empty body as `null`; the break-glass test uses the real helper. |
| 2 | P1: `NextProtos: ["http/1.1"]` does not decline HTTP/2 under `ServeTLS` — Go appends `h2`, and a client offering only `h2` negotiates it, against contract §13.5 and the HTTP/1.1 reasoning behind the refusal wrapper. The test inspects the config, not a handshake. | door | **Accepted.** `Server.Protocols` set to HTTP/1 only (plus an empty `TLSNextProto`), and a test that dials with `NextProtos: ["h2"]` and asserts the negotiated protocol. |
| 3 | P1 (both): a cookie-less `POST /api/fs/mkdir` on 8771 reaches `auditUnauthenticated` — a synchronous durable write plus a QuLog milestone per packet, outside the source bucket and `noteRefusal` — recreating the amplifier the login route's refusal throttle closed. | door | **Accepted.** Sessionless denials on the break-glass listener go through the bounded refusal accounting (one line per source per window, summary on return). |
| 4 | P1 (adv): the account-wide lockout lets any LAN peer lock the sole emergency account with five wrong passwords, renew the exclusion at each expiry within its source budget, and a password change does not reset it. | door | **Accepted, as a design change.** The lockout ladder is keyed by **source** (the bounded table the bucket already uses), so a peer can only lock itself out; the account-wide bound on guessing is the serialised bcrypt plus the per-source bucket. Contract §5.1 and §18 amended; flagged to the owner. |
| 5 | P1/P2: `watchForCredential` reloads the on-disk config and arms with its address; under `-dev` the start-up `forceLoopbackBreakGlass` is not reapplied, so setting the first password exposes the dev daemon on `0.0.0.0:8771`. | door | **Accepted.** The same forcing runs on the late-bind path. |
| 6 | P1/P2 (both): `list.js` turns the listing's display class (`browse.go`'s lexical `/etc`, `/usr`, `/var`… → `protected`) into `guard.denied`, and `whyDisabled` applies that cause to every action — so View, Download, Properties and Search are disabled under `/etc`, and an admin loses the repair operations the app exists for. | ui | **Accepted.** The guard cause applies only to mutating actions, and only where the class is what the guard actually refuses for everybody — never to reads. |
| 7 | P2 (both): `Locked()` is checked before the verification semaphore and `Failed()/Succeeded()` run after release: four queued attempts all see "unlocked", skip rungs, and a queued correct password succeeds during a lockout. | door | **Accepted.** The lockout verdict is re-checked and the outcome committed inside the serialised section. |
| 8 | P2 (both): `decodeBody`'s new drain (`io.Copy`) blocks with no read deadline — a valid JSON prefix under a larger `Content-Length`, then silence, parks the handler; the 15 s context does not interrupt socket reads. | door | **Accepted.** `ResponseController.SetReadDeadline` around decode and drain on the JSON routes; a drain that times out closes the connection instead of counting as consumed. |
| 9 | P2: explicit `certFile`/`keyFile` outside the protected tree are neither guarded nor mode-checked — a pair under a user-writable directory can be replaced by that user. | door | **Accepted, narrowed.** An admin who downloads their own key already has root, so that half is not an exposure; the writable-parent half is real and is refused at arm time with strict modes (parent not group/other-writable, owned by root), logged. |
| 10 | P2: validation checks `auth.local.cost` but not the hash: `hash: " "` arms a listener nobody can pass; an embedded cost of 31 runs bcrypt for minutes per attempt. | door | **Accepted.** A non-empty hash must parse as bcrypt with a cost in range. |
| 11 | P2 (both): turning read-only off in Settings updates `state.session` without repainting the banners, so *no changes can be made* stays up while changes are enabled. | ui | **Accepted.** Settings routes through `showSession`. |
| 12 | P2 (both): the credential's `updated` stamp changing under a live daemon is not audited (contract §6.2), and the CLI writes nothing by design — a rotation can leave no record. | door | **Accepted.** `localCred` reports a changed stamp once; the door emits the milestone. |
| 13 | P2 (both): `/api/logout` destroys a break-glass session silently; only `/api/breakglass/logout` audits; expiry and eviction in `issue` are silent too. | door | **Accepted.** Every removal reports once with its reason (logout, expired, evicted). |

| 15 | P2: `localCred` reloads with production `config.Load`, so a `-dev` config (`auth.mode local/both`) can never log in; the initial load error is ignored. | door | **Accepted.** The dev flag is carried into `localCred`. |
